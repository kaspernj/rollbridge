Recover now recognizes a persisted state that conclusively names a dead guardian — its recorded pid is gone and nothing is listening on its Unix socket — and, once every orphaned process is confirmed stopped, archives the state under a timestamped evidence name (bytes preserved verbatim) while moving the dead socket metadata aside, instead of clearing it. A later deploy can then boot a fresh generation through the ordinary recovery path. This automates the manual state-level recovery for the documented dead-guardian dead-end (host precedent archived 2026-08-30 and 2026-09-21; TensorBuzz production runbook `docs/production-rollbridge-recovery.md`), where every boot path previously failed with no automatic recovery. Any ambiguity in the provenance check keeps the existing fail-closed behavior.
